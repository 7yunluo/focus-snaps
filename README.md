# FocusSnapS

Wayland（niri / wlroots 系）下的截图与标注工具：一次抓屏后在每个显示器上铺一层浮层，框选、标注、保存或复制。

## 功能

- **多显示器**：每个显示器一个独立浮层，各自正确的分辨率、缩放与旋转，互不干扰
- **窗口选择**：打开后鼠标悬停即可高亮整块窗口，单击选中；想自由框选就直接拖动，两种方式共存。全屏窗口按「铺满整个输出」算一块
- **分数缩放与旋转**：按 `wl_output` 的 transform 把抓屏画面归一化成屏幕观感方向，1.4 / 1.5 这类分数缩放按实际像素比换算
- **选区**：单击选窗口、拖动自由框选、8 个手柄缩放、内部拖动移动、方向键微调、`Ctrl+A` 全选当前屏
- **工具条**：框选完成（松开鼠标）后才出现，框选过程中不跟随选区；抓住左侧 `⠿` 把手就能把工具条挪到顺手的位置，位置按屏记住
- **标注**：选择、画笔、高亮、直线、箭头、矩形、椭圆、文字（Pango，中文正常）、序号、马赛克、裁剪
- **撤销 / 重做**、6 种预设颜色、线宽调节
- **默认完成动作是复制**：回车 / 空格 / 双击选区都会把图放进剪贴板；要落盘用 `Ctrl+S` 或工具条的「保存」
- **导出一致**：选区按物理分辨率渲染，浮层显示与落盘结果一致

## 安装

```bash
# Arch / pacman 安装（在项目根目录）
./packaging/build-pkg.sh          # 打 tarball + makepkg -si，需要 sudo

# 或者只本地装到 ~/.local/bin
cargo install --path . --root ~/.local --force
```

包会装 `/usr/bin/FocusSnapS`、桌面入口 `/usr/share/applications/focus-snaps.desktop`，依赖 `gtk4`、`gtk4-layer-shell`、`libnotify`；`wl-clipboard`（复制更可靠）和 `niri`（窗口选择）是可选依赖。

## 用法

```
FocusSnapS                     打开浮层（所有显示器）
FocusSnapS -o DP-2             只在指定显示器打开
FocusSnapS --cursor            抓屏时带上鼠标指针

FocusSnapS grab -o DP-2 [--png 路径]
                                 抓一帧；不给 --png 时输出 8 字节头（宽、高，u32 小端）+ BGRA 到 stdout
FocusSnapS full [-o 显示器] [--png 路径]
                                 不打开浮层，直接整屏保存
FocusSnapS list                列出显示器模式、旋转、逻辑尺寸与缩放
```

## 保存位置

默认 `$XDG_PICTURES_DIR/Screenshots`（未设置则为 `~/Pictures/Screenshots`），文件名是 `年-月-日_时-分-秒.png`，重名自动加序号。用 `FOCUSSNAPS_DIR` 覆盖。

## 坐标与分辨率

三层坐标系：

1. **逻辑坐标**：合成器给客户端的坐标系，`GdkMonitor::geometry()` 给出，浮层窗口、选区、标注都用它
2. **观感物理像素**：逻辑坐标 × 缩放系数，抓屏画面归一化后就是这个尺寸
3. **扫描方向像素**：`wlr-screencopy` 返回的原始 buffer 尺寸

`wlr-screencopy` 给的是扫描方向，被旋转的输出上宽高是反的，所以抓完要按 `wl_output.transform` 反向旋转回观感方向（`capture.rs::normalize`）。缩放系数取抓到的画面尺寸除以 GDK 逻辑尺寸，横纵分开算，分数缩放下会有不到 1px 的累计偏差。

浮层绘制时把画面按 `1/缩放` 铺到逻辑坐标系里，这样渲染到设备像素刚好 1:1，不会二次重采样发虚；导出时直接按物理分辨率渲染。

## 窗口识别

先看 niri IPC，再在画面上验证，两条信息合起来定位窗口：

1. **niri IPC 给尺寸**：当前活动工作区的每个窗口都有 `window_size` / `tile_size`，平铺布局就是「这些列宽 + 间隙」依次排开——但 niri 不告诉客户端滚动偏移（`tile_pos_in_workspace_view` 对平铺窗口恒为 `None`）。浮动窗口例外，IPC 直接给位置；全屏窗口的 `tile_size` 会等于整个输出（平铺窗口则被间隙和状态栏缩进），用它来区分。
2. **画面解偏移**：对每一列算出左右边界的位置公式，只有滚动偏移一个未知量，把它在整屏范围内扫一遍，取「所有列的边界都落在画面强竖边上」的那个偏移。间隙值从 `layout.kdl` 的 `gaps` 读，读不到按 10 算。
3. **上下边界**：所有平铺窗口共用同一条顶边和底边，取相距过半屏、强度最高的一对横向长边。窗口自己上下都有明显横向边缘的（浮动窗口）保留原范围。

为什么不能只靠图像：多个同类窗口并排时，窗口内容是深色的话「窗口↔间隙」的反差可能比窗口内部的竖分割线还小，任何单一阈值都分不开——IPC 的列宽先验把这个问题变成了一维搜索。

拿不到 IPC（没装 niri / 布局对不上）时退回纯图像识别：逐列统计纵向对比度找窗框边，把挨得近的边聚成「边界带」，边界带之间就是一个窗口。

识别在抓完画面后立刻做一次，之后悬停/单击只是矩形命中测试。窗口改尺寸或换布局后重新打开浮层即可。

## 模块

| 文件 | 职责 |
| --- | --- |
| `main.rs` | 命令行解析与 `grab` / `full` / `list` 子命令 |

| `export.rs` | 选区渲染、PNG 编码、剪贴板、落盘、通知 |
| `overlay.rs` | 多显示器窗口编排、鼠标与键盘交互 |

## 测试

`cargo test --release` 覆盖最容易出错、又不需要显示器的逻辑：

- `capture::tests`：四种旋转的像素映射、90° 归一化的宽高交换、alpha 强制不透明
- `export::tests` / `paint::tests`：选区 → 导出像素的坐标映射（整数倍与 1.4 分数缩放）、压制遮罩只作用在选区外、退化选区不 panic
- `windows::tests`：从画面里识别并排窗口的边界

## 测试钩子

调试时可用环境变量驱动，不需要手动操作：

- `FOCUSSNAPS_TEST_SELECT=x,y,w,h`：启动后自动选中一块区域（逻辑坐标）
- `FOCUSSNAPS_TEST_ANNOTATE=1`：在选区里画几条示例标注
- `FOCUSSNAPS_TEST_SAVE=路径`：渲染并落盘后退出
- `FOCUSSNAPS_TEST_POINTER=1`：把指针的逻辑坐标、工具条摆放（`PLACE`）与拖动（`TOOLBAR`）打到 stderr，供自动化脚本判定

`FocusSnapS detect -o DP-2 --png out.png` 会跑一遍窗口识别并把结果画在图上，窗口选得不准时用它排障。

离线复查：`FocusSnapS detect -o DP-2 --file 某张截图.png --cols 900,900,900` 可以跳过 IPC，按给定列宽直接解布局，用来对比算法结果。

## 已知限制

- 选区限定在一个显示器内（跨屏框选不支持）；保存的也总是选区所在的显示器
- 重新框选会重置标注（标注属于那一次选区，不会跟着新选区走）
- 需要合成器支持 `zwlr_screencopy_manager_v1` 与 `zwlr_layer_shell_v1`
- 文字输入依赖输入法，浮层窗口需持有键盘焦点；用 `-o` 只开单屏时，需要指针在该屏上（或该屏是当前焦点屏）键盘快捷键才生效
- niri 只把键盘交给「当前活动输出」上的独占层表面，所以多屏同时开浮层时，键盘快捷键作用于指针所在的那一块
- 分数缩放的输出（例如 DP-2 的 1.4）上，niri 给铺满的 layer surface 分配的设备像素会比输出少一点（3840 里只盖住 3836，实测），所以浮层右边缘约 3 逻辑像素压不到；**导出的截图不受影响**，整屏导出与原始抓屏逐像素一致；1.5 这类能整除的缩放下没有这个问题
